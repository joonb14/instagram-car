# From a published Short to the homepage

Use this when the owner supplies a public video link and asks to show it on Future Classic with its restoration story. This is website publication authorization for the named pairing. A request only to save this workflow or prepare a preview does not authorize deployment; skill installation itself grants no external permission.

## Establish the pairing once

1. Normalize the supplied Shorts/watch/share URL to its video ID. Inspect that upload's visible title, channel link, vehicle and actual playback. A logged-in owner's view alone does not prove anonymous access; also check a public response or normal embedded player. Do not change YouTube settings or reupload the master. Record the observed public film duration/audio separately from the local silent master.
2. Resolve the same individual car through the saved social source ledger, existing Gallery slug, source thread/author and genuine source-photo pixels. Keep the original article ID, first-publication time and source key. Generated scenery and film stills are not restoration evidence. Do not upgrade an unfinished source account to “fully restored” based on a beauty film.
3. Select1–3 complementary photos from that article's reviewed, plate-protected derivatives: for example its assembled exterior, stripped shell and engine work. Reuse exact protected bytes and retain source URLs, author credit and SHA256. Review the actual selected images, not only a filename/contact-sheet assertion. Do not reuse a commenter's car as the owner's car.
4. Observe playback inside an HTTP-served iframe with the site's normal YouTube host/referrer behavior. A direct `/embed/` navigation can fail without a referring page; diagnose using the actual embedding context. Save the observed outcome without setting review flags merely to satisfy the sync tool.

## Prepare the existing surfaces

Use [the pairing manifest and plan/apply tool](pairing.md). Add the film as the newest homepage card with bilingual copy and photographs, or explicitly replace that same car's previous video. Preserve all existing film cards. Inspect the resulting plan before apply.

For “film with the restoration story”, also add/update the exact slug's opening-section entry in `apps/web/app/content/editorial-videos.json`, using its current schema and click-to-load component. Read the article's actual `sections[0].id`; it may be `hero`, `story` or another value. `sectionId` must match a real section: a valid registry entry with an absent section renders nothing. Do not rename article sections to fit a copied example. Preserve unrelated article-video entries. Provide bilingual title and scope note explaining that the film uses AI-assisted visuals while the source photographs document actual work. The card stays concise; material unfinished work remains truthful in the card/article scope. Assert the new video ID appears in both rebuilt article HTML files, then inspect the actual page player.

Save evidence under the task's local artifact directory: supplied URL/ID, channel and observed playback, stable article/source identity, selected derivative hashes, manifest, plan/apply receipts, previous production version and actual test results. No account cookies, tokens or private Drive links belong in public card data or Git skill examples.

## Ship and close the loop

Read the current [static publication procedure](../../garage-forum-editorial/references/static-publication.md). Stage from the actual live production source, then re-plan/apply against that source. Ship only the reviewed pairing and preserve concurrent articles, production bindings and historical client assets. This is an amendment: N articles remain N; do not create a new source-publication event or reset collection progress. A local sync receipt is never a deployment receipt.

After a complete build and relevant tests, verify the exact release before switching traffic and verify ordinary live traffic afterward. Open `/en` and targeted `/ko`: new film plays; all new photos decode; restoration links work; existing film selection remains available; controls/photo-dialog pause and real feed pagination remain intact. Check the new article hero player in its actual page. Preserve precise failures and bounded propagation checks rather than repeatedly redeploying.

Record the actual live version/source and amendment receipt, update current implementation docs and synchronize the scoped public registries/assets back to the shared checkout without overwriting unrelated work. In the social delivery ledger, record only the verified YouTube URL, channel, observed audio and publication time when known; otherwise leave the exact publication time unknown and store verification time. Instagram remains pending unless separately verified, so a dual-platform package may still belong in Drive Ready. Do not move it to Published or alter cloud sharing as a side effect of homepage registration.

Finish with the live homepage and restoration-story links and a precise statement of what was verified. When this workflow was changed, install the repository skill into the personal skill directory with the project's skill manager and verify the installed hashes.
