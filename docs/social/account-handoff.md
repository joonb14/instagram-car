# 다른 계정·PC에서 이어하기

## 저장소 역할

- [diy-cars](https://github.com/joonb14/diy-cars): 웹사이트 프로젝트 코드, AGENTS.md, 구현 문서와 제작 스킬·도구 원본.
- [instagram-car](https://github.com/joonb14/instagram-car): 다른 환경에서도 설치할 수 있는 제작 스킬 7개와 실행 도구의 검수된 배포 사본. 사이트 DB·원문 수집·운영 배포 전체를 포함하지 않습니다.

제작 도구는 `scripts/instagram/`, 홈 영상 연결 도구는 `scripts/home-films/`, 설치 도구는 `scripts/skills/`가 단일 구현입니다. 여러 스킬 안의 실행 파일을 따로 고치지 않습니다. 배포 사본을 갱신할 때 양쪽 변경을 먼저 비교하고, 독립적으로 수정된 쪽을 덮어쓰지 않습니다. 새 구현은 diy-cars에서 검수하고 instagram-car에 같은 소스와 공개 가능한 출처 기록을 동기화합니다. 자동 Git 동기화는 설정하지 않았습니다.

## 시작 절차

Node.js 24 이상, npm 11을 사용합니다. 현재 OS 사용자·환경의 일반 Node를 사용하며 이전 PC의 절대 실행 파일 경로를 복사하지 않습니다.

웹사이트 작업이면 diy-cars를 복제해 `AGENTS.md` → `docs/README.md` → 해당 기능 문서를 읽습니다. 영상 제작만 한다면 instagram-car를 복제해 그 저장소의 README와 AGENTS.md부터 읽습니다.

```sh
git clone git@github.com:joonb14/diy-cars.git
cd diy-cars
npm ci
npm run skills:check
npm run skills:test
npm run skills:install
npm run skills:check -- --installed
```

이미 개인 스킬이 있으면 최초 설치 명령에서 멈추는 것이 정상입니다. 먼저 원본과 설치본의 차이를 확인하고 보존할 편집을 가져온 뒤 `npm run skills:install -- --update`로 갱신합니다. 기본 대상은 현재 `CODEX_HOME/skills`, 환경 변수가 없으면 현재 사용자의 `~/.codex/skills`입니다. 설치 도구는 관리 대상 이외의 개인 파일을 삭제하지 않습니다. 기존 작업 폴더를 다른 Codex 계정에서 그대로 쓰는 경우에도 먼저 설치본 검사를 하며 무조건 재설치하지 않습니다.

실제 영상 인코딩에는 별도 FFmpeg가 필요합니다. `FFMPEG` 환경 변수 또는 PATH로 지정합니다. 없으면 관련 테스트가 건너뛰어진 사실을 그대로 보고합니다. Python 이미지 도구에는 Pillow·NumPy를 별도로 준비합니다. 웹/DB 개발 설정은 프로젝트 README와 예시 환경 파일을 따르며 실제 인증 값은 Git에 넣지 않습니다.

## 작업을 시작할 때 전달할 문구

> AGENTS.md와 docs/social/account-handoff.md, docs/README.md를 읽고 현재 저장소 상태를 확인해줘. 기존 Future Classic 스킬을 적용해서 이어가되, 필요한 비공개 자료와 로그인 상태는 먼저 실제로 확인해줘. 과거 대화나 작업 영수증이 복원됐다고 가정하지 마.

그 뒤 이번 차량·원문·원하는 작업 범위와 실제 접근 가능한 자료 폴더를 전달합니다. 이 안내는 과거 대화를 대체하는 실행 규칙이며, 비공개 작업 이력을 꾸며내는 근거가 아닙니다.

## 꼭 유지할 제작 결정

- 기반 이미지부터 9:16, 영상용 최종 입력은 실제 1080×1920. 주체 참고 사진과 영상 시작 프레임은 용도가 다릅니다.
- 보통 Kling 3.0, 3초, 1080p, 9:16, 오디오 끔. 현재 승인된 배치에서는 Generate 1회 24크레딧을 실제 UI로 확인합니다. 다른 비용이면 설정과 현재 승인 범위를 다시 확인합니다.
- 주체 태그는 `@` 선택 목록에서 실제로 연결됐는지 확인합니다. 글자만 타이핑한 태그를 연결 완료로 취급하지 않습니다.
- 차량의 실제 구조·로고·레터링·번호판·와이퍼를 원문 사진에서 분석합니다. 실차의 비대칭을 임의로 가운데 정렬하지 않습니다. 번호판 없는 제작 방침과 사용자가 선택한 구도·조명을 보존합니다.
- 카메라만 작은 궤도로 움직이고 차체 위치·방향·타이어 접지는 지면에 고정합니다. 기존 성공 사례를 우선하되 다른 차량에 같은 디테일을 이식하지 않습니다.
- 유료 생성은 한 건씩 제출·검수합니다. 진행 중 결과는 5분 간격으로 확인하고, 최초 지정한 배치 수에서 멈춰 피드백을 기다립니다. 새 계정에서도 과거 배치 승인을 새 유료 배치의 무제한 허가로 삼지 않습니다.
- 완성차 영상은 디테일에서 전체로 펼치는 구성을 선호하며 앞 사선 전체 컷을 마지막에 둘 수 있습니다. 비포·애프터는 별도 스킬을 씁니다. 기존에 승인된 예시를 모든 작업에 강제하지 않습니다.
- 최종본과 Instagram 캡션·YouTube 제목·설명은 Drive Ready에 개별 파일로 전달합니다. ZIP은 요청할 때만 만듭니다. 작업 입력·실험은 Review에 두고 플랫폼별 실제 게시 확인 후 Published로 이동합니다.
- 공개 YouTube 링크를 받아 사이트에 연결할 때는 home-films 스킬로 정확히 같은 원문 차량과 매칭합니다. 대문·기존 복원기·실제 사진과 한영 플레이어를 확인합니다. 게시글 첫 섹션 ID가 항상 `hero`라고 가정하지 않습니다.

자세한 최신 기준과 성공 프롬프트는 해당 스킬의 참조 문서를 사용합니다. 이 요약과 실제 원문·사용자 최신 요청이 다르면 최신 근거를 우선합니다.

## Git으로 복원되지 않는 것

Kling·Drive·사이트 배포 계정의 로그인, 토큰·인증키, 원본·생성 영상, `artifacts/`·`.local/`의 실행 영수증과 미완료 작업 상태는 복제되지 않습니다. 같은 계정을 다시 연결하거나 권한을 부여받은 계정으로 접근합니다. 기존 주체 태그와 유료 생성 결과도 실제 Kling 작업 공간에서 확인해야 합니다.

새 PC에서는 필요한 작업 파일을 소유자의 비공개 Drive/로컬 백업에서 받아 명시적인 프로젝트 상대 경로로 연결합니다. 경로만 남은 성공 사례는 미디어 파일이 존재한다는 증거가 아닙니다. 비공개 Drive ID나 작업 토큰을 안내 문서에 추가하지 않습니다.

## 웹사이트 운영 상태와 작업 사본

2026-10-27 확인된 운영 버전은 `a3608668-d888-4050-a28f-9646b3a44b7a`입니다. 당시 게시글129편, 한영 정적문서258개, 홈 영상4개였고 차저 공개 영상 `8w0_tLwZPCQ`가 기존 복원기와 연결됐습니다. 이후 작업에서는 실제 Cloudflare 운영 버전을 다시 확인합니다.

GitHub 백업은 작업 사본이며 운영 배포가 아닙니다. 로컬에 함께 진행 중이던 기능 변경도 있으므로 저장소 전체가 현재 운영 소스와 같다고 가정하지 않습니다. 이전 배포의 검증된 소스와 상세 영수증은 비공개 `artifacts/`에 있고 Git에서 제외됩니다. 새 PC에 해당 자료가 없다면 실제 운영 소스를 확보·확인하기 전 운영 릴리스를 덮어쓰지 않습니다. 로그인·DB·수집 자동화 설정을 복제만으로 변경하지 않습니다.
